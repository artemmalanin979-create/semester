# AGENTS.md — правила для ИИ-агентов проекта «Семестр»

Этот файл задаёт обязательный инженерный, визуальный и этический контракт для любых ИИ-агентов (Codex, Antigravity, субагентов аудита и вёрстки), работающих с репозиторием.

## 1. Этика, данные и пометка концепта
- Используй **исключительно вымышленные данные** (персонажи, учебные группы, договоры, приказы и оценки придуманы для демонстрации).
- Нигде не используй официальный логотип, герб или фотографии реальных корпусов вуза. Каждая сгенерированная иллюстрация используется ровно в одном месте (`/login` → `campus.webp`).
- На **каждой** странице (включая `/login`, `/staff`, `/verify/<token>`, страницы ошибок `400`/`403`/`404`/`429` и печатные бланки) обязана присутствовать строка:
  `Концепт для конкурса MGIMO × AI Challenge. Не официальный сервис вуза. Все данные вымышлены.`
- На всех бланках справок и квитанций обязателен водяной знак `ОБРАЗЕЦ / ДЕМО`. На экране финансов — явная пометка об имитации оплаты.

## 2. Безопасность и изоляция аккаунтов
- Идентификатор и роль пользователя (`student` / `staff`) определяются только на сервере по `SHA-256` от ключа сессии в таблице `login_sessions`.
- Любой запрос к приватным записям (`requests`, `charges`, `guest_passes`, `room_bookings`, `office_slots`) обязан фильтроваться по `student_id = g.student['id']`. При чужом или несуществующем идентификаторе возвращай `404`.
- Маршруты `/staff*` доступны только роли `staff` (для студентов возвращают `404`).
- Все `POST`-запросы обязаны проверять CSRF-токен сессии (`secrets.compare_digest`), а создание заявок — одноразовый `nonce` (`UNIQUE(student_id, nonce)`).
- Вход `/login` ограничен по частоте: максимум 5 неудачных попыток за 10 минут на `(email, IP)` (`HTTP 429`).
- Строгий `Content-Security-Policy: default-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`. В шаблонах **запрещены** атрибуты `style="..."` и inline-блоки `<script>`.
- Никаких секретов, токенов и продакшен-паролей в коде или git-истории (только `.env.example`, пароли хранятся исключительно как `scrypt`-хэши).

## 3. Дизайн-система и доступность
- Эстетика: функциональная чистота (`Adwaita` + `Revolut`), без градиентной дымки, свечений, эмодзи и самореференсного ИИ-копирайта.
- Палитра: спокойный зелёный акцент `oklch(.265 .042 160)` в светлой теме и каноническая монохромная лестница `oklch(.17 0 0 → .95 0 0)` в тёмной теме (`prefers-color-scheme: dark` + `[data-theme="dark"]`).
- Шрифты локальные (SIL OFL): `Adwaita Sans` для интерфейса и `JetBrains Mono` (`.num`, `tabular-nums`) для расписаний, рейтингов, сумм и реестровых кодов.
- Иконки: единый линейный SVG-набор `1.75px`; у каждой кнопки без текста обязателен `aria-label`. Мобильные зоны нажатия `≥ 44 px`.
- Навигация студента: максимум 6 разделов в боковом меню и максимум 5 пунктов в нижнем таб-баре на `360 px`.
- Один экран — одна тема: несвязанные блоки разводятся по подвкладкам (`?tab=`), подвкладки — обычные ссылки (без JS, с клавиатуры, deep link для ассистента).
- Услуги и справки показываются по правилам профиля (`demo.eligibility`): военкомат — только мужчинам на воинском учёте, стипендия — только бюджетникам, общежитие — только проживающим.

## 4. Верификация перед коммитом
1. Прогнать модульные тесты: `python -m unittest discover -s tests -v`.
2. Проверить вёрстку в браузере (Playwright / Browser Subagent) на `360×800` и `1440×900` в обеих темах: `scrollWidth == clientWidth`, ноль ошибок консоли и `CSP`.
3. Делать небольшие осмысленные коммиты без трейлеров `Co-Authored-By`. Подробные планы и спеки лежат в `docs/plan-final.md`, `docs/design.md` и `docs/superpowers/`.
